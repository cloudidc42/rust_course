# แนวทางการเขียนเนื้อหาหลักสูตร (Style Guide)

เอกสารนี้ใช้เป็นมาตรฐานกลางสำหรับเขียนเนื้อหาทุก Part ในหลักสูตร เพื่อให้เนื้อหาสอดคล้องกัน
ไม่ว่าใคร (หรือ agent ตัวไหน) จะเป็นคนเขียน

## กฎทั่วไป

- ภาษาเนื้อหา: **ภาษาไทย** เป็นหลัก (คำศัพท์เทคนิค/ชื่อฟังก์ชัน/ชื่อ crate ให้คงเป็นภาษาอังกฤษตามต้นฉบับ)
- ความยาว: แต่ละ Part ควรมี **500–3000+ บรรทัด** (รวมโค้ด) เนื้อหาต้อง "ใช้งานได้จริง 100%" ไม่ใช่โครงร่างลอย ๆ
- โค้ดทุกตัวอย่าง**ต้อง compile ได้จริง**ด้วย Rust edition 2021 ขึ้นไป (ตรวจสอบ syntax ให้ถูกต้อง แม้ไม่มี cargo ให้รันจริง ก็ต้องเขียนให้ถูกต้องตามหลักภาษา)
- ห้ามเขียนเนื้อหาเป็น bullet สั้น ๆ ล้วน ๆ โดยไม่มีคำอธิบาย — ต้องอธิบายเชิงลึกว่า "ทำไม" ไม่ใช่แค่ "ทำอย่างไร"
- อ้างอิงเนื้อหาก่อนหน้าได้ (บอกว่า "จาก Part ที่ N เราได้เรียน...") แต่ห้ามสมมติว่าผู้อ่านรู้เนื้อหาที่ยังไม่ได้สอน
- ห้ามใส่ข้อมูลที่เป็นความลับ, credential, หรือ URL ที่ไม่เกี่ยวข้อง

## โครงสร้างบังคับของแต่ละ Part (Markdown Template)

```markdown
# Part {N}: {ชื่อบท}

> โมดูล: {ชื่อโมดูล} | ระดับ: {พื้นฐาน/กลาง/สูง/มืออาชีพ} | เวลาโดยประมาณ: {X} นาที

## เป้าหมายของบทเรียน

- (bullet list สิ่งที่ผู้เรียนจะทำได้หลังจบบทนี้ 3-6 ข้อ)

## ความรู้ที่ต้องมีมาก่อน

- อ้างอิง Part ก่อนหน้าที่เกี่ยวข้อง

## เนื้อหา

### {หัวข้อย่อยที่ 1}
คำอธิบายเชิงลึก + โค้ดตัวอย่าง + คำอธิบายโค้ดทีละส่วน

```rust
// โค้ดตัวอย่างที่รันได้จริง พร้อม comment อธิบาย
fn main() {
    // ...
}
```

อธิบายผลลัพธ์ที่ได้ และเหตุผลเชิงลึก (ownership/borrow checker/performance/design เหตุผลอะไรก็ตามที่เกี่ยวข้อง)

### {หัวข้อย่อยที่ 2, 3, 4, ...}
(ทำซ้ำรูปแบบเดียวกัน ลึกและละเอียดพอที่จะได้ 500-3000+ บรรทัด)

## กับดักที่พบบ่อย (Common Pitfalls)

- อธิบาย error ที่มักเจอ พร้อมวิธีแก้ และ error message จริงจาก compiler ถ้าเกี่ยวข้อง

## แบบฝึกหัด (Exercises)

1. โจทย์ระดับง่าย
2. โจทย์ระดับกลาง
3. โจทย์ระดับยาก / ประยุกต์ใช้งานจริง

(ควรมีเฉลยแบบย่อหรือ hint ท้ายข้อ ไม่ต้องเฉลยเต็มทุกข้อ)

## สรุป

- สรุปสิ่งที่เรียนไปแบบกระชับ
- เชื่อมโยงไปยัง Part ถัดไป

---

**Part ก่อนหน้า:** [{ชื่อ}](part-{N-1}-slug.md) | **Part ถัดไป:** [{ชื่อ}](part-{N+1}-slug.md)
```

หมายเหตุสำคัญ: ไฟล์ part ทั้งหมดอยู่ใน `parts/` directory เดียวกัน (เป็น sibling กัน) ลิงก์ prev/next
**ต้องเป็นชื่อไฟล์เปล่า ๆ** เช่น `part-005-style-tools-rustfmt-clippy.md` **ห้ามใส่** `../parts/` หรือ path
นำหน้าใด ๆ ทั้งสิ้น — นี่คือข้อผิดพลาดที่เกิดขึ้นซ้ำ ๆ ในอดีต ให้ตรวจสอบลิงก์ท้ายบทอีกครั้งก่อนส่งงานเสมอ

## การตั้งชื่อไฟล์

`parts/part-{NNN}-{english-kebab-slug}.md` เช่น `parts/part-001-intro-and-setup.md`
เลขบทใช้ 3 หลักเสมอ (001, 002, ..., 110) เพื่อให้ไฟล์เรียงลำดับถูกต้องในทุกระบบ

## ตัวอย่างโค้ดที่ควรมีในทุกบท (ตามความเหมาะสมของหัวข้อ)

- ตัวอย่าง "ผิด" ที่ compiler ไม่ยอมให้ผ่าน พร้อม error message และวิธีแก้ (ช่วยให้เข้าใจว่าทำไม Rust ถึงออกแบบมาแบบนี้)
- ตัวอย่างเปรียบเทียบกับภาษาอื่น (เช่น C++/Python/JavaScript) เมื่อช่วยให้เข้าใจง่ายขึ้น
- ตัวอย่างจากโลกจริง ไม่ใช่แค่ `foo`/`bar` ล้วน ๆ (เช่น ระบบจัดการสินค้าคงคลัง, ระบบจองตั๋ว, ระบบธนาคารง่าย ๆ)

## Checklist ก่อนส่งบทเสร็จ

- [ ] มีหัวข้อและโครงสร้างตาม template ครบ
- [ ] จำนวนบรรทัด ≥ 500 (ควรอยู่ 800-3000+ สำหรับหัวข้อที่ซับซ้อน)
- [ ] โค้ดทุกก้อน syntax ถูกต้องตามภาษา Rust ปัจจุบัน (2021 edition+)
- [ ] มีลิงก์เชื่อม Part ก่อนหน้า/ถัดไปที่ท้ายบท
- [ ] อัปเดตสถานะใน `docs/curriculum.md` จาก ⏳ เป็น ✅
